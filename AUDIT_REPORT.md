# Giftora engineering audit

Audited 8 November 2026. The application consists of a Next.js 16 App Router frontend, a FastAPI service, SQLAlchemy models, a MySQL schema script, and connector/agent modules. No Alembic revision files are present, so the SQL schema remains the database bootstrap source.

| Severity | Issue | Affected files | Root cause | Fix / verification |
| --- | --- | --- | --- | --- |
| High | AI extraction accepted arbitrary model JSON and replaced every failure with an opaque heuristic result. | `backend/app/services/ai_service.py` | No parsing boundary or field validation. | Fixed with fenced-JSON parsing, Pydantic normalization, bounded fields, explicit fallback logs, and resilience tests. |
| High | Production could start with a committed development JWT secret and permissive development CORS behavior. | `backend/app/core/config.py`, `backend/app/main.py` | Defaults were valid in every environment. | Fixed: production startup validates `DEBUG`, secret strength, and explicit origins. |
| High | Database health always appeared connected because a non-empty health dictionary is truthy. | `backend/app/main.py`, `backend/app/api/routes/health.py` | Truthiness used instead of the `connected` field. | Fixed: response exposes boolean and returns 503 when unavailable. |
| Medium | Error responses were inconsistent; unexpected database errors could surface as framework defaults. | `backend/app/main.py` | No centralized exception mapping. | Fixed: validation, SQLAlchemy, and unknown-error handlers now return stable error envelopes. |
| Medium | Frontend lint failed due to synchronous state writes in effects. | `src/components/layout/*`, `src/context/*` | Client hydration effects violate the React lint rule. | Fixed and verified with `npm run lint`. |
| Medium | Production build depended on remote Google Fonts, making offline/restricted builds fail. | `src/app/layout.tsx`, `src/app/globals.css` | `next/font/google` downloads during build. | Fixed with system-font fallbacks; Webpack build produced the production output. |
| Medium | Marketplace connectors advertise configured providers as active but contain no live request implementation; development mocks use sample URLs and fabricated catalog metadata. | `backend/app/connectors/*.py` | Connector API calls have not been implemented. | Unresolved: keep them documented as mock-only until official provider clients and credentials are implemented. |
| Medium | Search persistence creates placeholder products from connector results and swallows persistence errors. | `backend/app/api/routes/search.py` | Demo flow is coupled to persistence without an error contract. | Unresolved: replace placeholders with validated source records and return a logged persistence state. |
| Medium | `database/schema.sql` drops tables and is unsafe for any existing deployment; Alembic has no revisions. | `database/schema.sql`, `backend/alembic/` | Bootstrap script is used as migration strategy. | Unresolved: create additive Alembic revisions before modifying deployed schema; never execute the bootstrap script against production. |
| Low | Frontend still uses local-storage product/recipient state alongside backend APIs, allowing stale views and offline demo behavior. | `src/context/GiftoraContext.tsx`, `src/data/*` | Migration to backend source of truth is incomplete. | Unresolved: progressively move wishlist, recipients, and comparisons to authenticated API queries. |
| Low | Navigation links point to `/inspiration` and `/videos`, but no matching routes exist. | `src/components/layout/Navbar.tsx`, `src/components/layout/AppSidebar.tsx` | UI navigation outpaced route implementation. | Unresolved: add the routes or remove/disable the links. |
